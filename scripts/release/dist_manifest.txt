# Single source of truth for what ships in a Praxen distribution.
# Read by build.sh (the release zip) and by
# scripts/release/stage_plugin_payload.sh (the vendored plugin payload the
# community catalog installs). Keeping one list is the point: if these two
# consumers ever disagree on what "the distribution" is, users installed from
# the catalog and users unpacking the zip are running different products.
#
# Format: one repo-root-relative path per line, optionally followed by the
# tag `zip-only`. Untagged entries ship in both the zip and the plugin
# payload; `zip-only` entries ship only in the zip (human-browsing content —
# they are what turns a ~1 MB skill into a ~10 MB install if vendored).
# Blank lines and lines starting with # are ignored.
#
# tests/ is deliberately absent from both: tests are for contributors, not
# operators. The payload stager additionally drops
# .claude-plugin/marketplace.json (the repo's legacy marketplace mirror —
# catalog metadata, not plugin payload).
