BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is a sandbox with the shape of isolation but permissive
defaults. The recommended Docker path gives real host-filesystem isolation and
enforces working-directory confinement and a wall-clock timeout — but out of
the box CodeExecutorAgent auto-approves every code block (the approval_func
defaults to None, emitting only a warning), the container is created with
unrestricted network egress and no CPU/memory/pids ceiling, and no durable
audit record of executions is written. Combined, these defaults turn an
upstream prompt injection into an unattended inject-execute-exfiltrate chain
that leaves no forensic trail. Separately, the LocalCommandLineCodeExecutor
and JupyterCodeExecutor run generated code directly on the host with no
isolation — the local executor even copies the parent process's full
environment (host secrets included) into the child — and
create_default_code_executor silently falls back to the local executor with
only a warning when Docker is unavailable.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-27-001  Default configuration yields an unattended
            inject-execute-exfiltrate chain — auto-approved execution plus
            unrestricted container egress plus no audit trail.
      Action 1: Ship a safe-by-default posture for the recommended path —
                require an approval function (or explicit opt-out) and create
                Docker containers with `network_mode="none"` unless an
                operator allow-list is configured.
      Action 2: Add a durable per-execution audit record (executor kind,
                language, source agent, work_dir, timeout, exit status, code
                digest) so the chain is at least detectable after the fact.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-27-002  CodeExecutorAgent auto-approves every code block when
            no approval function is set, emitting only a warning.
      Action: Make an approval function mandatory for production, or default
              to a deny-until-configured posture, so execution is gated unless
              the operator explicitly opts into auto-approval.

  PRAX-2026-07-27-003  Docker executor creates containers with unrestricted
            network egress and no allow-list mechanism.
      Action: Default containers to network_mode="none" and expose an
              explicit, operator-configured egress allow-list, so outbound
              access is opt-in rather than on by default.

  PRAX-2026-07-27-004  Local and Jupyter host executors run generated code
            unisolated with full host filesystem and parent-environment
            access.
      Action 1: Pass a minimal, explicitly-constructed environment (not
                os.environ.copy()) to executed subprocesses, stripping host
                credentials.
      Action 2: Make the local-host fallback in create_default_code_executor
                fail closed (raise) unless the operator explicitly authorises
                host execution.
