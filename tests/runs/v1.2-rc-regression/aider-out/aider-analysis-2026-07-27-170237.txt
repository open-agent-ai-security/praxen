BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is a genuine human-in-the-loop safety model that is
strong exactly where it matters most and thin everywhere else. The
highest-impact action — executing an LLM-proposed shell command — is gated by
a confirmation that shows the exact command and holds even under
`--yes-always` (`io.confirm_ask` returns "n" for `explicit_yes_required` when
blanket-yes is set), which breaks the classic one-hop injection-to-RCE chain
and is why this scan raises no Critical. But that same rigor is absent from
adjacent surfaces: untrusted file/web/comment content reaches the model
unlabeled with no injection neutralization, edit paths are never confined to
the repository root, and the ordinary (non-`explicit_yes_required`)
confirmations for package installs and out-of-repo edits are silently
auto-approved under `--yes-always`. The result is an agent whose deterministic
controls are concentrated on exec and supply-chain pinning while input-trust,
path-confinement, and telemetry-scope boundaries rely on developer vigilance
rather than code.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-27-001  Edit-target paths are never confined to the repository
            root, so an absolute or `../` path escapes the repo with only a
            bypassable confirmation.
      Action 1: In base_coder.abs_root_path, reject or refuse any path whose
                resolved location is not under self.root (e.g. verify
                os.path.commonpath([resolved, root]) == root) instead of
                relying on the un-added-file confirmation.
      Action 2: Make edits to files outside the repository root refused
                outright rather than gated by an ordinary confirm_ask that
                `--yes-always` bypasses.

  PRAX-2026-07-27-002  All untrusted content enters the LLM context unlabeled
            with no injection neutralization, so embedded instructions can
            steer Aider's edits.
      Action 1: Wrap externally-sourced content (scraped pages, file bodies,
                watch comments, command output) in explicit untrusted-content
                delimiters and add a system-prompt directive that instructions
                inside such content must never be obeyed.
      Action 2: Prefer this content-origin labeling over relying solely on the
                human confirmation gate, which does not cover injection-driven
                edits to files already in the chat.

  PRAX-2026-07-27-003  `--yes-always` silently auto-approves package installs
            and out-of-repo edits; only shell execution is exempted from
            blanket-yes.
      Action 1: Pass explicit_yes_required=True to the confirmation in
                check_pip_install_extra and to the allowed_to_edit prompts for
                un-added/new files so `--yes-always` cannot auto-approve
                installs or out-of-repo writes.
      Action 2: Alternatively, gate package installs and out-of-repo writes
                behind a separate flag that `--yes-always` does not satisfy.
