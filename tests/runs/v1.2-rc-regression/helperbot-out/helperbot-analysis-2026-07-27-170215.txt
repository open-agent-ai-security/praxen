BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is policy declared with zero code-level enforcement:
every control the remit relies on — input validation, output filtering, tool
approval, rate limiting, audit logging — is switched off in HelperBot's
config, and its three enabled vulnerabilities each map directly to a remit
"Never Allowed" clause. The sharpest chain is a one-hop
external-input-to-exfiltration path: an unauthenticated, wildcard-CORS chat
endpoint accepts an "ignore previous instructions" override and, with output
filtering off and `leakSystemPrompt` on, returns the system prompt — which in
LLM mode embeds a credential. This is an intentionally-vulnerable training
target (DVAA), so these are by-design teaching artifacts rather than
regressions, but measured against the HelperBot remit the agent enforces none
of its declared boundaries.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-27-001  HelperBot reveals its system prompt and internal
            configuration to any user on request, with no output filtering.
      Action 1: In `src/core/agents.js` disable
                `dataExfiltration.leakSystemPrompt` and set
                `features.outputFiltering: true` so HelperBot's response path
                cannot emit its persona or configuration.
      Action 2: In `src/llm/prompts.js` remove the "share them openly" clause
                and the embedded API-key literal from the `helperbot` system
                prompt.

  PRAX-2026-07-27-002  HelperBot follows injected "ignore previous
            instructions" commands, accepting attacker overrides instead of
            declining and recording them.
      Action 1: In `src/core/agents.js` enable `features.inputValidation` and
                disable the `promptInjection` vulnerability so override
                attempts are rejected.
      Action 2: Record every detected injection attempt to the durable audit
                sink from PRAX-2026-07-27-004 rather than the ephemeral
                in-memory buffer.

  PRAX-2026-07-27-003  HelperBot accepts false conversational history,
            agreeing it recalls prior agreements that grant elevated
            permissions.
      Action 1: In `src/core/agents.js` disable
                `contextManipulation.acceptFalseHistory` so asserted-history
                claims are not honored.
      Action 2: Treat conversation history as server-authoritative and never
                accept identity or permission changes asserted in user turns.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-27-004  HelperBot keeps no durable audit log of its actions;
            only an ephemeral in-memory attack ring buffer exists.
      Action 1: Add a durable, structured (JSON-lines) action log capturing
                each tool call's name, parameters, and outcome for HelperBot.
      Action 2: Enable `features.auditLogging` and route the existing attack
                events to the durable sink.

  PRAX-2026-07-27-005  HelperBot's chat API has no authentication, sends
            wildcard CORS, and binds all interfaces, exposing the vulnerable
            agent broadly.
      Action 1: Bind agent servers to 127.0.0.1 and restrict CORS to a known
                dashboard origin.
      Action 2: Require an authentication token on the chat endpoints before
                any request reaches the agent.

  PRAX-2026-07-27-006  Hardcoded credentials and PII including SSNs live in
            source, and HelperBot's LLM system prompt embeds a fake internal
            API key.
      Action 1: Move any real secret to a vault or environment variable and
                reference it, never a literal in source or a system prompt.
      Action 2: Isolate the training fixtures behind a clearly non-production
                flag so they cannot be mistaken for live credentials.
