BEHAVIOR SUMMARY
------------------------------------------------------------------------------
Hermes is a security-conscious agent whose controls are real and operative
rather than declarative: an unconditional catastrophic-command floor,
fail-closed SSRF checks, non-overridable credential scrubbing, exact
dependency pinning with OSV screening, and an adversarial test suite tied to
named advisories all run on the agent's path. The dominant weakness is not an
absent control but a scoping gap in the one that matters most — the terminal
and execute_code approval gate auto-approves dangerous (non-hardline) actions
in any execution context it does not recognize as CLI, gateway, ask, or cron
(a documented headless-local limitation), and the screening it does apply is
pattern-based over a Turing-complete shell that execute_code's arbitrary
Python sidesteps entirely. The remaining findings are calibration issues
around that same axis — an opt-in aux-LLM approver, a redirect-based SSRF gap
in third-party web SDKs, free-form (non-structured) action logs, and a
regex-mitigated writable-memory persistence surface.
