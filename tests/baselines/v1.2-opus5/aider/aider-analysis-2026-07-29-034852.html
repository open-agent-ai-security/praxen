Executive Summary
Agent Remit (as declared)
An AI pair-programming assistant that runs in a developer's terminal and edits code in their local git repository in response to natural-language instructions, keeping every change under version control so the developer can diff and undo it. It may read and edit files the user has explicitly added to the chat, generate a repository map, commit through git, invoke linters and test commands, scrape web pages, ingest images and voice, and execute shell commands. Its only authorized counterparty is the local operator, and its only sanctioned outbound destinations are the operator-configured LLM provider and opt-in PostHog analytics. Every shell command — including auto-lint and auto-test — must require explicit operator approval, and instructions embedded in scraped pages, file contents, or command output must never be treated as authoritative directives.
Behavior Summary (as observed)
Aider hardened exactly one control and left the rest of the perimeter open. The approval gate on model-suggested shell commands in run_shell_commands() is deliberate and genuinely non-bypassable — confirm_ask(explicit_yes_required=True) makes even --yes-always answer "no" — but that discipline appears nowhere else: repository-supplied .aider.conf.yml and .env reconfigure the agent and reach subprocess(shell=True) through the auto-lint path with no prompt at all, and watch_code_prompt instructs the model to follow instructions written into source-file comments while files_content_prefix tells it to trust file contents outright. The result is a one-hop path from attacker-authored repository content to unreviewed edits and commits, with --gui publishing a fully auto-approving instance on every network interface as the sharpest variant.
Scope of Analysis
A Python CLI (aider.main:main) built on litellm, with a Coder class hierarchy in aider/coders/ that assembles the system prompt, applies edit blocks, and drives git through aider/repo.py. Approval prompts are centralized in InputOutput.confirm_ask() in aider/io.py; shell execution runs through aider/run_cmd.py with shell=True, reached from /run, /git, the linter, and the model's own suggested commands. Configuration is auto-discovered from .aider.conf.yml and .env in the working repository, and an experimental Streamlit UI in aider/gui.py is launched by launch_gui(). Untrusted material — scraped pages, command output, and AI comments found by aider/watch.py — is appended to the conversation as user-role messages with no provenance marking, and no domain allowlist gates /web.

Maturity Scoring Rubric

Every score above is based on this scale. A score is a snapshot of observable posture — not a verdict on the people or team behind the system.

Score Label Meaning
5 Exemplary Best-in-class; automated, continuously tested, reference quality. Rarely achieved in shipping systems.
4 Strong Comprehensive controls, active management, minor gaps. Production-ready.
3 Established Documented controls consistently applied; known gaps accepted. A respectable baseline.
2 Partial Some controls exist but coverage is incomplete; key gaps remain.
1 Ad hoc Informal or inconsistent measures; relies on individual judgment.
0 Absent No evidence this category is addressed at all.
Weighting: the weighted overall above is the sum of each category's score × weight (the per-category weights are shown on each card). Zero Trust carries double weight by design; see the RAISE framework reference for the rationale.
