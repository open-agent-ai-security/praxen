BEHAVIOR SUMMARY
------------------------------------------------------------------------------
Aider hardened exactly one control and left the rest of the perimeter open.
The approval gate on model-suggested shell commands in run_shell_commands() is
deliberate and genuinely non-bypassable —
confirm_ask(explicit_yes_required=True) makes even --yes-always answer "no" —
but that discipline appears nowhere else: repository-supplied .aider.conf.yml
and .env reconfigure the agent and reach subprocess(shell=True) through the
auto-lint path with no prompt at all, and watch_code_prompt instructs the
model to follow instructions written into source-file comments while
files_content_prefix tells it to trust file contents outright. The result is a
one-hop path from attacker-authored repository content to unreviewed edits and
commits, with --gui publishing a fully auto-approving instance on every
network interface as the sharpest variant.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-001  Shipped prompts instruct the model to obey instructions
            written into repository file contents, with no provenance labeling
            on any ingested content.
      Action 1: Wrap all non-operator content — watch_prompts.py AI-comment
                blocks, cmd_web output, and prompts.run_output — in an
                explicit untrusted-data delimiter and add a standing
                system-prompt clause stating that text inside it is data,
                never instructions.
      Action 2: Change watch_code_prompt so AI comments are presented as a
                request to be summarized for operator confirmation rather than
                instructions to follow, and require an explicit confirm before
                FileWatcher.process_changes() promotes a newly-discovered file
                into abs_fnames.

  PRAX-2026-07-29-002  Repository-supplied .aider.conf.yml and .env set the
            lint and test commands, which auto-lint then executes through
            shell=True with no approval prompt.
      Action 1: Gate the first execution of a repository-supplied lint-cmd or
                test-cmd behind confirm_ask(..., explicit_yes_required=True)
                showing the exact command, reusing the control already applied
                to model-suggested commands at base_coder.py:2456.
      Action 2: Ignore lint-cmd, test-cmd and yes-always when they originate
                from a config file inside the working repository rather than
                the operator's home directory or the command line.

  PRAX-2026-07-29-003  aider --gui publishes an unauthenticated, fully
            auto-approving coder on every network interface; no server address
            is pinned to loopback.
      Action 1: Append --server.address=127.0.0.1 to st_args in launch_gui()
                so the experimental UI cannot be reached off-host, and add an
                explicit opt-in flag for any non-loopback bind.
      Action 2: Remove the unconditional yes=True from get_coder() in
                aider/gui.py and surface confirmations as Streamlit dialogs,
                so GUI sessions retain the same per-action approval model as
                the CLI.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-004  allowed_to_edit() enforces neither repository-root
            containment nor .aiderignore, so model-supplied paths can escape
            the operator's declared scope.
      Action 1: In allowed_to_edit(), reject any path whose resolved form is
                not is_relative_to(self.root) before any confirmation is
                offered, mirroring the guard already present at watch.py:95.
      Action 2: Add a self.repo.ignored_file(path) check alongside the
                existing git_ignored_file() check at base_coder.py:2202 so
                .aiderignore and --subtree-only bind the model's edit path,
                not just file addition.

  PRAX-2026-07-29-005  Every aider commit passes --no-verify by default,
            silently skipping the repository's configured pre-commit hooks
            without operator authorization.
      Action 1: Flip the --git-commit-verify default to True in
                aider/args.py:494 so hooks run unless the operator explicitly
                opts out, and surface a one-line notice when the operator does
                disable them.
      Action 2: When a hook rejects an aider commit, report the hook output to
                the operator rather than falling back to a bypass.

  PRAX-2026-07-29-006  --yes-always auto-approves every destructive file and
            git confirmation; only model-suggested shell commands carry the
            flag that resists it.
      Action 1: Set explicit_yes_required=True on the destructive
                confirmations in allowed_to_edit() — "Create new file?" and
                "Allow edits to file that has not been added to the chat?" —
                so --yes-always cannot widen the edit surface beyond the files
                the operator added.
      Action 2: Split the flag into --yes-always for informational prompts and
                a separate, explicitly-named option for destructive ones, so
                scripted runs cannot silently inherit both.
