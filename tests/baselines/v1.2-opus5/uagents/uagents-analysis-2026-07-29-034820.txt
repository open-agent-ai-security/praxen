BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is a runtime that authenticates its peers but never
authorizes them. Envelope signatures are genuinely verified with ECDSA in
asgi.py and envelope.py, yet nothing downstream asks whether a verified sender
is an authorized counterparty: the AccessControlList that would answer that
question lives in the opt-in QuotaProtocol and defaults to allow-all, and the
signed envelope carries expires and nonce fields that the receive path never
checks, so a captured message replays forever. Compounding this, the
agent-inspector REST routes are on by default behind a loopback check that
forwarded_allow_ips="*" makes spoofable on a 0.0.0.0 bind, putting /connect —
which re-registers the agent's signed identity against a caller-supplied
endpoint URL — within reach of any remote client.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-001  Default-on agent-inspector routes sit behind a
            spoofable loopback check on a 0.0.0.0 bind, letting any remote
            caller re-register the agent's identity.
      Action 1: In asgi.py, replace forwarded_allow_ips="*" at line 184 with
                the operator-configured trusted-proxy list (uvicorn's
                127.0.0.1 default when unset), and make HOST at line 23 a
                constructor parameter defaulting to 127.0.0.1.
      Action 2: Flip enable_agent_inspector at agent.py:305 to default False,
                and require an operator-supplied bearer token on /connect,
                /disconnect, /messages and /agent_info rather than relying on
                a network-position check.

  PRAX-2026-07-29-002  The shipped Helm chart carries a working default agent
            seed in values.yaml, deriving a publicly-known identity and wallet
            for any chart-default deployment.
      Action 1: Remove the literal from values.yaml:16, leave agent.seed
                empty, and make the chart fail rendering when it is unset
                (required in secrets.yaml) so a seed must be supplied per
                deployment.
      Action 2: Treat the committed phrase as compromised: rotate any agent
                identity or wallet ever deployed from chart defaults, and
                document seed provisioning in deployment/README.md.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-003  The runtime authenticates senders but never authorizes
            them — the counterparty allowlist is an opt-in protocol that
            defaults to allow-all.
      Action 1: Add an agent-level counterparty allowlist checked in
                _process_single_message() before handler dispatch, so
                authorization is enforced on the default Agent.on_message path
                rather than only inside QuotaProtocol.
      Action 2: Change the QuotaProtocol.wrap() fallback at quota.py:183 from
                AccessControlList(default=True) to deny-by-default, and
                require handlers marked allow_unverified to declare that they
                perform no state-changing action.

  PRAX-2026-07-29-004  Envelope expires and nonce fields are covered by the
            signature but never checked on receipt, so any captured message
            replays indefinitely.
      Action 1: In asgi.py, reject the envelope before dispatch when
                env.expires is absent or already past, mirroring the freshness
                the digest already commits to.
      Action 2: Populate nonce in context.py:509 and keep a bounded per-sender
                seen-nonce set in the agent's storage so a replayed envelope
                is dropped rather than re-handled.

  PRAX-2026-07-29-005  Synchronous response envelopes are built without a
            signature, and the requesting agent skips verification entirely
            when a signature is absent.
      Action 1: Sign the response envelope in enclose_response_raw() with the
                responding agent's identity before it is returned by the
                /submit sync path in asgi.py.
      Action 2: Change communication.py:157 to require a signature on any
                response whose sender is an agent address, rejecting unsigned
                responses instead of accepting them.

  PRAX-2026-07-29-006  No approval gate, threshold or authorization flag
            exists on any wallet-spending path, and Almanac registration
            spends funds automatically at startup.
      Action 1: Add a value_transfer_approval_threshold parameter to
                Agent.__init__ and interpose a policy check in network.py
                before any transaction carrying funds is broadcast, halting
                and logging when the amount exceeds it or authorization is
                absent.
      Action 2: Make paid Almanac registration opt-in — when no authorization
                flag is set, register through the fee-free Agentverse API path
                and surface the skipped on-chain registration to the operator.

  PRAX-2026-07-29-007  Identity and wallet private keys are auto-generated
            into a plaintext JSON file in the working directory with default
            permissions and no guard.
      Action 1: Create private_keys.json with 0o600 (open with os.open(...,
                O_CREAT|O_WRONLY, 0o600)) in save_private_keys(), and fail
                loudly if an existing file is group- or world-readable.
      Action 2: Emit an explicit warning from
                _initialize_wallet_and_identity() when keys are auto-persisted
                to disk, and document the seed-from-environment path as the
                supported production configuration.

  PRAX-2026-07-29-008  get_or_create_private_keys persists a freshly generated
            wallet key that is not the one it returns, so the running wallet's
            key is never saved.
      Action 1: In storage/__init__.py:149, pass the already-generated
                wallet_key to save_private_keys() instead of calling
                PrivateKey() a second time.
      Action 2: Add a regression test asserting that two successive
                get_or_create_private_keys(name) calls return the same wallet
                key and that it matches the persisted file.
