Executive Summary
Agent Remit (as declared)
A self-hosted, single-owner personal agent that plans and executes multi-step computer and browser tasks, generates and runs code at runtime, builds and operates local Living UI applications, and maintains a local RAG-backed memory. Its authorized capability set is file read and edit within its own workspace, sandboxed code and shell execution, web search and fetch, document generation, memory search, installed Skills, configured MCP servers, and the actions of external integrations the owner has explicitly connected. The single owner-operator is the only authorized counterparty, and third parties reaching the agent over a connected platform are never authoritative direction. Runtime code and shell execution must run in an isolated sandbox, every irreversible or externally-visible action requires explicit owner approval before execution, and any listener the agent starts must bind to loopback.
Behavior Summary (as observed)
Every boundary this remit declares exists in CraftBot as prompt text rather than code. The single interposition on the action path is an idempotency ledger for irreversible=True actions — a de-duplication check, not an approval gate — so the approval requirements, permission tiers, harness-managed-file protections and third-party-message rules are all instructions the model is asked to honour rather than controls that can refuse. The sharpest consequence is a one-hop chain: a message or web page from an untrusted source is interpolated into the model's context behind a text label, and the same session can call run_shell, which runs with shell=True directly on the host with the parent process environment — including the owner's provider API keys — and no isolation beyond a shared virtualenv. Reinforcing the pattern, the repository ships a complete injection-detection module at app/security/prompt_sanitizer.py that has zero call sites anywhere in the codebase.
Scope of Analysis
Python agent harness — app/ holds the runtime, where agent_base.py orchestrates sessions, actions, triggers and the scheduler over a reusable agent_core/ framework, with craftos_integrations/ supplying the OAuth and credential layer for roughly two dozen third-party services. Tools are @action-decorated Python functions loaded from app/data/action/; run_shell, write_file, read_file, http_request and the integration send actions all sit in the default core set. Actions execute through agent_core/core/impl/action/executor.py, whose "sandbox" is a reusable virtualenv under ~/.craftbot/sandbox_venv rather than an OS boundary. Persistent state spans a ChromaDB vector memory, SQLite stores at usage/actions.db and usage/sessions.db, and a markdown agent file system (AGENT.md, SOUL.md, USER.md, MEMORY.md, PROACTIVE.md) that is loaded into context and writable by the agent's own file tools, while app/config/mcp_config.json ships 157 MCP server definitions with auto-connect enabled.

Actions flagged irreversible record INTENT to a SQLite ledger before the side effect and are refused re-execution when the ledger shows a completed or interrupted run, so a crash or redelivery cannot silently repeat an external send.
