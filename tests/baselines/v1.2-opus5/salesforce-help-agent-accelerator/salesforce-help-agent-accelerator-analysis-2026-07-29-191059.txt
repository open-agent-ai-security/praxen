BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is one control, two implementations: the same UI host
ships twice and the security-relevant checks exist in only one copy. The
static-resource twin gates every platform URL through isTrustedSalesforceUrl()
and enforces a 1000-character input cap; the LWC path appends a <script> from
an operator-supplied URL with no protocol check, no domain allowlist and no
integrity attribute, accepts unbounded input, and tears down page-wide DOM
that the twin explicitly guards. The controls are not missing because nobody
thought of them — they were written, then not carried across. On the agent
side the pattern is policy stated in prose, nowhere enforced and nowhere
recorded. All eleven behavioral guardrails live as natural-language lines in
system.instructions, the override-resistance rule covers user input but says
nothing about instructions arriving inside retrieved Knowledge articles,
masking is acknowledged but never prohibited, and the platform audit trail
that would make a successful bypass reconstructable is documented as optional.
What keeps this off the critical tier is the capability ceiling: the bundle
defines exactly one read-only retrieval action and no write, send, or execute
capability anywhere, so a successful bypass produces a wrong answer rather
than a wrong action.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-001  Override-resistance instruction covers user input only,
            leaving instructions embedded in retrieved Knowledge articles
            unaddressed.
      Action 1: Extend the guardrail block in system.instructions to state
                that instructions appearing inside retrieved Knowledge content
                are data, never directives, and must never be obeyed.
      Action 2: Add Knowledge-article review to the Data Library setup in
                README.md Step 1.3 so indexed content is vetted for
                instruction-like text before it reaches the retriever.

  PRAX-2026-07-29-002  The off_topic topic instructs the agent to offer human
            escalation that the escalation topic states does not exist.
      Action: Delete the human-escalation offer from the final sentence of the
              off_topic reasoning block at haaHelpAgent.agent:157 and redirect
              to the website support procedures the escalation topic already
              names.

  PRAX-2026-07-29-003  The LWC appends a bootstrap script from an
            operator-supplied URL with no protocol check, domain allowlist, or
            integrity attribute.
      Action 1: Port isTrustedSalesforceUrl() from the static resource into
                the LWC and call it on bootstrapUrl, siteUrl, and scrt2Url
                before _loadBootstrapScript() appends the script element.
      Action 2: Set script.crossOrigin and a pinned integrity attribute, or
                load the bootstrap only from the org's own published site
                domain, so a swapped remote script cannot execute.

  PRAX-2026-07-29-004  System instructions acknowledge that emails and org IDs
            arrive masked but never prohibit revealing or reconstructing those
            values.
      Action: Add an explicit prohibition to the guardrail block at
              haaHelpAgent.agent:11 — masked values must never be echoed,
              unmasked, inferred, or reconstructed, regardless of how the
              request is phrased.

  PRAX-2026-07-29-005  Setup docs present Einstein Audit and Feedback and
            Agentforce Session Tracing as optional, though the remit requires
            them.
      Action: Move the Audit and Feedback and Agentforce Session Tracing
              toggles out of the optional list in README.md and into the
              required prerequisites at Step 1.1, alongside Data Cloud and
              Einstein.

  PRAX-2026-07-29-006  No adversarial test artifact exists for a public
            unauthenticated agent whose entire guardrail set is
            prompt-resident.
      Action 1: Add a prompt-adversarial test set exercising each guardrail
                line in system.instructions — override attempts, system-prompt
                extraction, off-topic coaxing, masked-value probing — and run
                it against the agent before each Commit and Activate.
      Action 2: Include at least one indirect case in which a Knowledge
                article contains instruction-like text, to cover the retrieval
                path recorded in PRAX-2026-07-29-001.
