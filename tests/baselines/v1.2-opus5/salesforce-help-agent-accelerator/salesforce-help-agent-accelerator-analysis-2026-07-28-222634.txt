BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is policy declared in the prompt with zero code-level
enforcement, on a surface that is also unmonitored. Every behavioral
obligation in the remit — jailbreak resistance, no system-prompt disclosure,
no off-topic answers, no ungrounded answers, no fabricated links — exists only
as natural-language lines in haaHelpAgent.agent, with no deterministic gate,
output filter or grounding check anywhere in the package, while the audit and
tracing features that would record a bypass are documented as optional and
shipped disabled. The second theme is control asymmetry between the two UI
hosts: the static-resource embed enforces an HTTPS Salesforce-domain
allowlist, a 1000-character query cap and a scoped teardown guard, and the LWC
that ships alongside it enforces none of the three.

CRITICAL FINDINGS

  PRAX-2026-07-28-001  Every declared guardrail is unenforced prompt text on
            an unauthenticated public chat surface, and no audit trail exists
            to detect a bypass.
      Action 1: Enable Einstein Audit and Feedback and Agentforce Session
                Tracing as a deployment prerequisite rather than an optional
                step, and promote them out of the "Optional for monitoring"
                table in README.md into the required setup in Step 1.1.
      Action 2: Move the disclosure and instruction-override guardrails off
                the prompt and onto a deterministic layer — configure Einstein
                Trust Layer masking and prompt-defence for this agent, and
                treat the lines in haaHelpAgent.agent as defence-in-depth
                rather than the control.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-28-002  The package ships no durable audit trail — agent
            tracing and audit features are documented as optional and the
            bundle contains no logging configuration.
      Action 1: Make Einstein Audit and Feedback plus Agentforce Session
                Tracing required steps in README.md Step 1.1 and state that
                the agent must not be activated without them, since they are
                the only mechanism that records what the agent was asked and
                how it answered.
      Action 2: Document a retention and review expectation for the resulting
                audit data so the trail is usable for incident reconstruction
                rather than merely present.

  PRAX-2026-07-28-003  The LWC injects a remote script from an unvalidated
            design-time URL, while its sibling static resource enforces a
            Salesforce-domain allowlist on the same value.
      Action 1: Port isTrustedSalesforceUrl() from the static resource into
                haaInlineEnhancedChat.js and call it on the resolved
                bootstrapUrl, siteUrl and scrt2Url before
                _loadBootstrapScript() appends the script element.
      Action 2: Extract the allowlist into a shared module consumed by both
                hosts so the two implementations cannot drift apart again.

  PRAX-2026-07-28-004  Grounding and citation obligations are prompt-only, and
            the package ships citations disabled with empty RAG and citation
            configuration.
      Action 1: Set citations_enabled: True and populate citations_url and
                rag_feature_config_id in haaHelpAgent.agent, or document them
                as required Step 1.4 configuration, so the agent has a real
                attribution channel behind its "Always include sources"
                instruction.
      Action 2: Add an ungrounded-answer and fabricated-link test set to the
                Step 1.6 agent testing checklist, since the link-construction
                rules are currently asserted but never exercised.

  PRAX-2026-07-28-005  The off_topic topic tells the agent to offer a human
            handoff that the escalation topic forbids and that no shipped
            action can perform.
      Action 1: Delete the human-escalation clause from the off_topic
                reasoning block in haaHelpAgent.agent line 157 so both topics
                state the same policy, leaving only the redirect to supported
                topics.
      Action 2: If a human handoff is in fact intended for this accelerator,
                add it as a declared action with its own topic and update the
                remit, rather than leaving the capability asserted in one
                prompt and denied in another.

  PRAX-2026-07-28-006  Nothing in the package restricts retrieval to Public
            Knowledge Base articles; the agent ships with no user and an
            operator-built Data Cloud index of unbounded scope.
      Action 1: State the public-only default explicitly in README.md Step 1.3
                — instruct operators to scope the Agentforce Data Library to
                Public Knowledge Base articles and to add internal data
                categories only as a deliberate, documented decision.
      Action 2: Add a verification step to Step 1.6 that queries for a known
                internal-only article and confirms the agent cannot retrieve
                it, so the permission-set configuration is proven rather than
                assumed.
