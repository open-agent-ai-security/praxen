Executive Summary
Agent Remit (as declared)
A Go CLI and runtime that generates coding-agent configuration — hooks, skills, agents, slash commands, MCP and LSP servers — for Claude Code, OpenCode, Codex CLI, and GitHub Copilot CLI, and then runs alongside those agents as a hook dispatcher, a stdio MCP server, and a per-session audit store. Its authorized surface is seven MCP tools (yaah_scan_secrets, yaah_lint, yaah_check_command, yaah_doctor, yaah_session_info, yaah_planning_status, yaah_planning_init) and five hook handlers, communicating only over local stdio, the local filesystem, and git-over-HTTPS to a vetted catalog of pinned skill and agent repositories. The command guard and secret scanner are declared load-bearing safety controls that must fail closed and must never be downgraded to advisory mode. Detected secrets must never appear in any yaah output in cleartext, credentials must never be embedded in generated configuration, and the model must never self-trigger the /yaah:* workflow commands.
Behavior Summary (as observed)

The dominant pattern is a safety layer that is real but consistently one step weaker than its declared contract. The command guard genuinely fails closed, sanitizeID() genuinely blocks path traversal, and generated configuration never downgrades the host's permission or sandbox posture — but the secret scanner the remit calls fail-closed is registered on PostToolUse, so a credential-bearing write has already landed on disk before it is detected; the guard beside it is a seven-pattern denylist bound to the Bash tool alone; and Linter.LintFile() executes repo-resolved binaries such as npx prettier without routing them through that guard at all.

Compounding this, nothing defends the controls themselves: the hook block lives in a plain .claude/settings.json that the guarded agent can edit, and DisableModelInvocation is set by none of the twenty-nine generated commands, leaving /yaah:autonomous — a workflow that runs an entire phase with no human checkpoint — model-invocable in direct contradiction of the remit. The audit trail is the second theme: structured, durable and genuinely reconstructive for hook-dispatched events, yet the whole yaah serve MCP surface writes nothing to it.

Scope of Analysis
Go 1.25 module built on a uniform Interface to Registry to Generator pattern: pkg/harness wires seven typed registries and dispatches lifecycle events through HandleHookEvent(), pkg/hooks/handlers supplies the five built-in handlers, pkg/mcpserver serves the seven tools over mcp.StdioTransport, and pkg/generator emits per-target config into .claude/settings.json, .mcp.json, opencode.json, .codex/ and .copilot/. There is no network listener; the only outbound surfaces are git clone to pinned GitHub repositories via pkg/gitcache, an HTTP MCP endpoint at Pulumi, and npx fetches that launch the Context7 and Notion MCP servers. Subprocess execution is concentrated in Linter.LintFile(), which runs project-resolved lint binaries against a caller-supplied file path, and in gitcache.gitClone(). Two divergences from the remit's implied shape stand out: the secret scanner is registered on PostToolUse rather than a pre-write event, and DisableModelInvocation is plumbed through buildCommandMarkdown() but set by none of the twenty-nine generated /yaah:* commands.

Maturity Scoring Rubric

Every score above is based on this scale. A score is a snapshot of observable posture — not a verdict on the people or team behind the system.

Score Label Meaning
5 Exemplary Best-in-class; automated, continuously tested, reference quality. Rarely achieved in shipping systems.
4 Strong Comprehensive controls, active management, minor gaps. Production-ready.
3 Established Documented controls consistently applied; known gaps accepted. A respectable baseline.
2 Partial Some controls exist but coverage is incomplete; key gaps remain.
1 Ad hoc Informal or inconsistent measures; relies on individual judgment.
0 Absent No evidence this category is addressed at all.
Weighting: the weighted overall above is the sum of each category's score × weight (the per-category weights are shown on each card). Zero Trust carries double weight by design; see the RAISE framework reference for the rationale.
