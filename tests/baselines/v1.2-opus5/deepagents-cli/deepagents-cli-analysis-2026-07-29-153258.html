Executive Summary
Agent Remit (as declared)
A terminal-based, model-agnostic coding assistant that plans and executes software-engineering work inside the operator's project directory, using file read/write/edit/search, shell execute, web search and fetch, sub-agent delegation, and operator-configured MCP servers, skills, hooks and sandbox backends. Its sole authority is the local developer or CI identity that launched it, and its trusted outbound set is the closure of operator-configured LLM providers, MCP servers, sandbox providers and sub-agent deployments. Every side-effecting action — shell execution, file creation and editing, outbound web calls, sub-agent delegation — must pass an explicit human-approval gate, with headless auto-execution permitted only under an operator-scoped shell allow-list that may never be set to "allow everything". Content arriving from tool results, fetched pages, or repository files is data, never instructions.
Behavior Summary (as observed)

The dominant pattern is a strong control that stops at the edge of the interactive path. _add_interrupt_on gates ten side-effecting tools with fail-closed mode coercion, and the codebase repeatedly gets the hard parts right — a DNS-pinned SSRF guard in tools.py, a fail-closed per-server MCP trust prompt, symlink-re-verifying skill trust, secret-stripped hook environments. The parallel execution paths inherit none of it: _make_hitl_decision in client/non_interactive.py inspects only execute and unconditionally approves everything else, is_shell_command_allowed returns True before any pattern check when the allow-list is all, and js_eval ships enabled and intentionally un-gated.

That asymmetry produces the scan's one compound chain: project content reaches the system prompt unlabelled through local_context.py, the agent is prompted to persist learnings into the same AGENTS.md files it loads at the start of every session, and in headless mode the write_file that closes the loop is auto-approved — poisoning that survives into all later sessions. The same one-sided pattern governs credentials: hooks/env.py strips secrets before spawning hook subprocesses, while client/launch/server.py hands the runtime server the entire parent environment and sandbox_factory.py interpolates it into a script run on a third-party host.

Scope of Analysis
Python package deepagents_code — 434 files, roughly 82,000 lines — built on LangChain/LangGraph with a Textual TUI. The front end spawns an ephemeral langgraph dev subprocess bound to 127.0.0.1 on an OS-assigned port and drives it over HTTP+SSE through RemoteAgent; the graph is assembled in create_cli_agent, and _add_interrupt_on wires the human-in-the-loop gate across ten built-in tools plus every mutating MCP tool. Three approval modes exist — Manual, a classifier-backed Auto, and an acknowledged YOLO — while a separate headless path in client/non_interactive.py substitutes a shell allow-list for that gate entirely. Notable surfaces beyond the remit's picture: local_context.py appends bash-detected project content to the system prompt on every turn, integrations/sandbox_factory.py expands the local process environment into a setup script executed on a remote sandbox, and a QuickJS js_eval REPL ships enabled by default and deliberately outside the approval gate.

Policy Rule — R-32 (Worker Remit):
"Loading configuration, model-provider definitions, or skill/memory definitions MUST NOT cause arbitrary code to execute before those definitions have been validated."
libs/code/THREAT_MODEL.md:406 — "T9 detail — 'module-level code executes unconditionally during import — before the type check runs ... This applies to both `class_path` and the `_load_provider_profiles` path that uses `exec_module()`'" libs/code/THREAT_MODEL.md:258 — "TB11 inside/outside — `config._create_model_from_class` validates the `module:ClassName` format and checks issubclass(BaseChatModel) 'before instantiation', but 'Any side effects (file I/O, network calls, subprocess spawning) in the module's top-level scope execute before the type check'"
Recommended Action
  • Restrict `class_path` resolution in `config._create_model_from_class` to an operator-declared allowlist of module prefixes, and surface a one-time confirmation naming the module the first time a given `class_path` is loaded.
  • Apply the same allowlist to `_load_provider_profiles` so a provider package dropped on `sys.path` cannot execute through `exec_module` on the startup path.
What's Working Well

Controls and behaviors that are correctly implemented and verified during this scan. These represent areas where the agent's implementation aligns with its stated policy and security best practices.

DNS-pinned SSRF guard on agent-supplied URLs

_validate_url rejects hostnames resolving to private, loopback, link-local (including cloud IMDS), reserved, multicast or non-global addresses — unwrapping IPv4-mapped IPv6 and 6to4 first — and _pinned_dns pins the outgoing urllib3 connection to the vetted IPs so the fetch cannot be re-resolved. The docstring names LLM-supplied, possibly prompt-injected URLs as the motivating threat.

libs/code/deepagents_code/tools.py:50-200

Fail-closed project MCP trust prompt with per-server fingerprint scoping

Both stdio and remote project-level MCP servers require an explicit allow action; approvals bind to the project root plus that server definition's fingerprint, a changed command, URL or transport forces re-approval, and an unreadable user trust policy denies rather than prompts under an unknown deny list.

libs/code/deepagents_code/main.py:3332-3375

Skill trust store that survives post-approval symlink swaps

load_skill_content refuses any SKILL.md resolving outside the trusted roots, and load_trusted_skill_dirs re-verifies each stored entry resolves to itself, so neither re-pointing the discovery symlink nor replacing the approved directory grants access the operator never approved.

libs/code/deepagents_code/skills/trust.py:15-32

Secret-stripped environment for hook subprocesses

sanitize_hook_environ filters every variable whose name matches the secret-name policy before a hook command is spawned, so provider keys are not ambiently available to user-authored hook code.

libs/code/deepagents_code/hooks/env.py:18-33

Loader-hijack variables stripped from the runtime server subprocess

_SERVER_ENV_DENYLIST removes LD_PRELOAD, DYLD_*, NODE_OPTIONS, SSH_ASKPASS and PYTHONPATH before spawning the server, and the launch-time PYTHONPATH is relayed separately so it reaches only the approval-gated execute backend rather than the server interpreter's import path.

libs/code/deepagents_code/client/launch/server.py:67-92

Approval mode fails closed and unrestricted mode requires acknowledgement

coerce_approval_mode maps any invalid or unrecognised stored value to Manual, and YOLO requires a versioned one-time risk acknowledgement persisted 0600 inside a 0700 directory under a cross-process lock.

libs/code/deepagents_code/approval_mode.py:51-63

Autonomy budgets are implemented and enforced

--max-turns, --timeout (exiting 124 on expiry) and --max-retries are wired through to the run, and the LangGraph recursion_limit is validated against explicit minimum and maximum bounds.

libs/code/deepagents_code/config_manifest.py:62-78
