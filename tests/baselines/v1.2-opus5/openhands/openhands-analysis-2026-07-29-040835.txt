BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is a well-built authentication and secret-handling
machinery that the default deployment never switches on. get_dependencies()
returns an empty dependency list whenever SESSION_API_KEY is unset, so every
V1 router — sandboxes, secrets, settings, git and conversations — ships
unauthenticated, while the shipped container entrypoint binds 0.0.0.0:3000 and
LocalhostCORSMiddleware reflects any origin with credentials when no origin
list is configured. The controls that are operative sit one layer inward, on
paths the sandbox itself calls: validate_session_key enforces RUNNING-state
and ownership before releasing a secret, and jwt_service.py pins its JWE
algorithms — genuine engineering that a caller reaching the outer API never
has to pass. Reinforcing that gap, the /mcp mount exposes five
repository-write tools with no approval gate and no repository allowlist, and
nothing in the control plane writes a durable audit record of who invoked
them.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-001  Every V1 control-plane router ships unauthenticated by
            default while the shipped entrypoint binds a public interface.
      Action 1: In openhands/app_server/utils/dependencies.py, make
                authentication fail-closed: when neither SESSION_API_KEY nor a
                SAAS identity provider is configured, return a dependency that
                rejects the request rather than an empty list, and require an
                explicit opt-out flag for unauthenticated local use.
      Action 2: Change the containers/app/Dockerfile CMD and
                openhands/server/__main__.py to bind 127.0.0.1 by default,
                requiring an explicit host override for any non-loopback bind.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-002  CORS middleware admits any origin with credentials
            whenever no origin allowlist is configured, which is the default.
      Action 1: In LocalhostCORSMiddleware.is_allowed_origin, delete the
                development-mode fallthrough that returns True for
                unrecognised origins; keep only the explicit
                localhost/127.0.0.1 allowance and defer everything else to the
                parent class.
      Action 2: Set allow_credentials=False whenever permitted_cors_origins is
                empty, so an unconfigured deployment cannot serve credentialed
                cross-origin responses.

  PRAX-2026-07-29-003  Five MCP repository-write tools accept any repository
            name, with no approval gate and no operator allowlist.
      Action 1: Gate every write tool in mcp_router.py behind an
                operator-configured repository allowlist checked before the
                provider call, rejecting any repo_name outside it.
      Action 2: Attach the same authentication dependency the V1 routers use
                to the /mcp mount in app.py, and require an explicit human
                approval step for pull-request creation.

  PRAX-2026-07-29-004  The process runtime spawns the agent server directly on
            the host with a full copy of the app server's environment.
      Action 1: In _start_agent_process, build the child environment from an
                explicit allowlist of required variables instead of
                os.environ.copy(), so control-plane credentials never reach
                the agent process.
      Action 2: Require an explicit acknowledgement variable (e.g.
                OH_ALLOW_HOST_DIRECT_EXECUTION) in addition to RUNTIME=local
                before ProcessSandboxServiceInjector is selected in config.py.

  PRAX-2026-07-29-005  The default compose deployment mounts the host Docker
            socket into the application container, granting
            host-root-equivalent authority.
      Action 1: Replace the raw socket bind mount in docker-compose.yml with a
                scoped Docker access proxy that permits only the container
                lifecycle calls DockerSandboxService actually makes (create,
                start, pause, stop, remove, inspect on the oh-agent-server-
                prefix).
      Action 2: Document the socket mount as a privileged-deployment choice
                and provide a socket-free compose profile that uses the remote
                or process sandbox services instead.

  PRAX-2026-07-29-006  Git provider tokens and the JWT master key are written
            to disk in plaintext with no restrictive file mode.
      Action 1: Encrypt secret values at rest before writing in
                FileSecretsStore.store — the existing JwtService.encrypt_value
                already provides a JWE path — rather than serialising with
                expose_secrets=True.
      Action 2: Create the persistence directory with mode 0o700 and write
                .keys and secrets.json with mode 0o600 in encryption_key.py
                and file_store/local.py.

  PRAX-2026-07-29-007  CI workflows reference third-party actions by mutable
            tag, and several reusable workflows by the @main branch.
      Action 1: Pin every uses: reference in .github/workflows to a
                full-length commit SHA with the version in a trailing comment,
                prioritising the @main refs to OpenHands/release-actions,
                OpenHands/OpenHands-Cloud and OpenHands/extensions.
      Action 2: Add a CI check (e.g. a lint step or Dependabot with SHA
                pinning enabled) that fails any workflow introducing a non-SHA
                external reference.
