BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is a financial decision agent whose every declared
safeguard exists as description rather than enforcement. Thresholds, a
confidence requirement, and injection screening are all configured and
displayed, but _approve_invoice commits an approval and sets payment_processed
without consulting any of them, confidence_threshold has no consumer anywhere
in the codebase, and the regex detector only records a boolean. Sitting on top
of that is a full persistence chain: an unauthenticated POST
/api/admin/finbot/goals writes arbitrary natural language into custom_goals,
which is concatenated into the system prompt on every subsequent invocation
under a header instructing the model to let it override the safety goals above
— so one anonymous request permanently redirects every future decision, with
no actor recorded and no alert raised.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-001  Every admin control-plane route is unauthenticated on a
            public deployment, letting anyone rewrite FinBot's thresholds,
            fraud state, goals, and vendor trust.
      Action 1: Add an authentication and role check as a before_request hook
                on admin_bp in src/routes/admin.py, rejecting any caller
                without an authenticated finance-operator role.
      Action 2: Remove the public "Admin Portal" link from
                src/static/index.html and restrict the admin blueprint to an
                internal network path rather than serving it from the same
                public origin as the vendor portal.

  PRAX-2026-07-29-002  An anonymous POST writes arbitrary natural language
            into custom_goals, which is concatenated into every future system
            prompt as an explicit override of FinBot's safety goals.
      Action 1: Gate /api/admin/finbot/goals behind the authenticated admin
                check from PRAX-2026-07-29-001, and record each goal change
                with actor and prior value.
      Action 2: Stop letting stored goals outrank the safety goals: remove the
                "OVERRIDE ABOVE IF CONFLICTING" framing at
                src/services/finbot_agent.py:71 and enforce thresholds,
                confidence, and injection routing in code so no prompt text
                can waive them.

  PRAX-2026-07-29-003  approve_invoice marks any invoice approved and
            payment-ready with no check on amount, injection flag, or caller —
            the model's tool call is the only gate.
      Action 1: In _approve_invoice, before mutating the invoice, load the
                config and route to _request_human_review whenever
                invoice.amount >= config.manual_review_threshold or
                invoice.contains_prompt_injection is true.
      Action 2: Separate the approval decision from payment readiness so that
                payment_processed is never set by the agent path.

  PRAX-2026-07-29-004  confidence_threshold is declared, editable, and
            displayed in the admin console, but no code path ever reads it
            before approving an invoice.
      Action 1: In _approve_invoice, compare the model-supplied confidence
                against config.confidence_threshold and route to
                _request_human_review when it falls below.
      Action 2: Treat model self-reported confidence as untrusted input — pair
                the threshold check with a deterministic signal (amount band,
                vendor trust, injection flag) rather than relying on the
                number the model chooses.

  PRAX-2026-07-29-005  Unauthenticated callers can list every vendor's bank
            account, routing number, and tax ID, and submit invoices as any
            vendor they choose.
      Action 1: Remove bank, routing, and tax fields from the vendor
                serialization used by any vendor-facing route, keeping them to
                an authenticated finance-operator view only.
      Action 2: Require an authenticated vendor session and check that the
                session identity owns vendor_id in get_vendor,
                get_vendor_invoices, and submit_invoice.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-07-29-006  The fallback engine scores authority and urgency
            phrases from the invoice description and uses that score to
            auto-approve above threshold and past detected injection.
      Action 1: Delete the expedite overrides at
                src/services/finbot_agent.py:807-820 and :841-850 so no phrase
                count can raise an invoice past the manual-review threshold or
                past a detected injection.
      Action 2: Make the LLM-unavailable path fail closed — route every
                invoice to human review when self.client is None instead of
                running the phrase-scoring engine.

  PRAX-2026-07-29-007  Injection screening is a literal-phrase regex denylist
            whose only effect is setting a boolean; the flagged description
            still reaches the model as ordinary data.
      Action 1: Wrap vendor-supplied description text in an explicit
                untrusted-content delimiter in the tool result, and instruct
                the model in the system prompt that content inside it is data
                only.
      Action 2: Make the detector consequential rather than advisory — have
                contains_prompt_injection force routing to human review in
                code, so a bypassed pattern degrades detection rather than
                removing the control.

  PRAX-2026-07-29-008  Vendor-authored descriptions and model-generated
            reasoning are interpolated into innerHTML in both portals, giving
            stored script execution in the reviewer's browser.
      Action 1: Replace the innerHTML template literals in
                admin-dashboard.html and vendor-portal.html with element
                creation plus textContent for every model- or vendor-sourced
                field.
      Action 2: Add a Content-Security-Policy response header that disallows
                inline script execution for both portal pages.

  PRAX-2026-07-29-009  The public, unauthenticated invoice endpoint triggers a
            multi-call LLM orchestration with no rate limit, no per-caller
            quota, and no spend ceiling.
      Action 1: Add a per-IP and per-vendor rate limit in front of
                submit_invoice in src/routes/vendor.py, and cap the accepted
                description length.
      Action 2: Set a hard monthly spend ceiling on the OpenAI key and have
                _run_agent_orchestration fail closed to human review when the
                ceiling is reached.

  PRAX-2026-07-29-010  Vendor self-registration auto-approves any registrant
            into the trusted counterparty set with no verification or operator
            sign-off.
      Action 1: Set new registrations to status='pending' in
                src/routes/vendor.py and require an authenticated operator
                action before a vendor can submit invoices.
      Action 2: Check registrant email domains against the operator-configured
                vendor closure and surface out-of-closure registrations to
                admins as a trust expansion.
