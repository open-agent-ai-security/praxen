BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The interactive approval gate is real and carefully engineered, but the
headless path quietly removes it: client/non_interactive.py auto-approves
every non-shell tool (file writes and deletes, fetch_url, web_search, task)
without an interrupt, and a committed project .env can set
DEEPAGENTS_CODE_SHELL_ALLOW_LIST=all so a cloned repository turns on
unrestricted shell for itself. Because tool results and repo files (project
AGENTS.md, the Makefile excerpt) reach the model verbatim with no provenance
labeling, a single fetched page or poisoned file can steer an auto-approved
write into the user's AGENTS.md memory, persisting the injection into every
later session. Around that core, the autonomy and secrecy guarantees are
thinner than the remit requires: --max-turns only counts HITL resumes and so
never fires in headless runs, provider keys are forwarded wholesale to the
runtime server and every execute subprocess, and the loopback agent API is
unauthenticated.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-10-19-001  A committed project .env can set
            DEEPAGENTS_CODE_SHELL_ALLOW_LIST=all, so a cloned repository
            grants itself unrestricted, approval-free shell execution in
            headless runs.
      Action 1: Add DEEPAGENTS_CODE_SHELL_ALLOW_LIST, the
                approval/startup-mode keys,
                LANGSMITH_TRACING/LANGSMITH_ENDPOINT/LANGSMITH_API_KEY and
                provider *_BASE_URL variables to
                _PROJECT_DOTENV_DENIED_ENV_KEYS in config.py so only the
                shell, CLI flags or the user's global config can set them.
      Action 2: When a security-relevant setting would come from a
                project-level source, print it and require an explicit CLI
                flag (or refuse) in run_non_interactive() rather than honoring
                it silently.

  PRAX-2026-10-19-002  The remit puts an "allow everything" setting out of
            bounds, yet dcode ships three: --shell-allow-list all, --yolo, and
            [startup].mode = yolo.
      Action 1: Remove the all sentinel from parse_shell_allow_list() and the
                YOLO mode, or restrict them to runs inside a remote sandbox
                backend so host execution can never be fully ungated.
      Action 2: If an unrestricted mode is kept, require an explicit per-run
                confirmation in both TUI and headless paths and record its
                activation to a durable audit log.

  PRAX-2026-10-19-003  Injected content can persist across sessions: a
            headless run auto-approves edit_file into the user or project
            AGENTS.md, which MemoryMiddleware loads into every later session.
      Action 1: Treat every AGENTS.md memory source as a protected path:
                require explicit human approval for writes to it in all modes,
                and refuse such writes in headless runs unless an explicit
                flag allows memory updates.
      Action 2: Show a diff of memory-file changes at the next session start
                so a poisoned instruction is visible before it is loaded.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-10-19-004  Headless runs approve every non-shell side-effecting
            tool — file writes and deletes, fetch_url, web_search, task and
            async sub-agents — with no interrupt and no notice.
      Action 1: In run_non_interactive(), keep the interrupt map active for
                non-shell side-effecting tools and reject them by default (as
                HeadlessMCPGuardMiddleware already does for MCP), with
                explicit per-tool opt-in flags such as --allow-writes /
                --allow-web.
      Action 2: Print a one-line audit notice to stderr for every
                side-effecting tool executed in headless mode.

  PRAX-2026-10-19-005  --max-turns counts only HITL resume rounds, and
            headless runs never raise HITL interrupts, so the operator's turn
            budget does not bound autonomous tool loops.
      Action 1: Count model calls (or tool-call steps) server-side, for
                example with a middleware that raises once a per-run step
                budget is reached, and pass max_turns through ServerConfig so
                the cap applies inside the graph.
      Action 2: Until then, derive the run's recursion_limit from --max-turns
                so the flag has an enforced effect.

  PRAX-2026-10-19-006  Provider API keys and every other secret in the parent
            environment are copied wholesale into the runtime server and into
            each execute shell subprocess.
      Action 1: Build the execute environment from an allowlist (PATH, HOME,
                LANG, project-specific vars) or reuse sanitize_hook_environ()
                so secret-named variables are stripped by default, with an
                opt-in to pass named keys through.
      Action 2: Pass the runtime server only the provider keys for the
                configured model, not the full parent environment.

  PRAX-2026-10-19-007  Tool results, fetched pages and repository files —
            including project AGENTS.md, project skills and the Makefile
            excerpt — reach the model verbatim, with no provenance labeling,
            injection detection or halt-and-alert.
      Action 1: Gate repository-supplied AGENTS.md, skills and subagent
                definitions behind the same fingerprint-bound project-trust
                prompt used for .mcp.json.
      Action 2: Wrap tool results and project context in clearly delimited
                untrusted-content blocks, add explicit data-not-instructions
                guidance to system_prompt.md, and surface a warning in the
                approval dialog when the pending call follows instruction-like
                content from a tool result.
