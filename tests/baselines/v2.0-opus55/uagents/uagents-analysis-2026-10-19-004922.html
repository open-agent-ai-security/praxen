Executive Summary
Agent Remit (as declared) · Remit v1.3
An autonomous agent built on the Fetch.ai uAgents framework that runs operator-defined handlers, interval tasks and lifecycle tasks while cooperating with peer agents over the Fetch.ai network under its own cryptographic identity. It may send, receive and broadcast typed messages, register on the Almanac / Agentverse, resolve peers, use its own key-value store, sign with its identity and hold an on-chain wallet, talking only to its own inbound endpoint, an operator-enabled mailbox or proxy, the Almanac / Agentverse APIs, the ledger and resolved peer endpoints. Only signature-verified senders may drive state-changing actions, seed and key material must never leave the host or be committed, and discretionary wallet spends and new counterparties require operator approval. Debug and inspector endpoints must be off in production, or protected when on.
Behavior Summary (as observed)

The framework authenticates the front door and leaves the side doors open. ECDSA envelope verification is real and on by default for agent senders, but the defaults around it undo much of that: signed envelopes can be replayed indefinitely because expires and nonce are never checked, synchronous replies (including the agent's own) travel unsigned and are accepted as authentic, and any verified address on the open network reaches every signed handler because there is no default peer allowlist.

The worst single item is the default-on inspector. On a 0.0.0.0 server with forwarded_allow_ips="*" and wildcard CORS, its 127.0.0.1 guard can be met by a forged X-Forwarded-For or by any web page in the operator's browser. That exposes message history and lets a caller make the agent sign an Agentverse identity proof under the caller's own token. Wallet funds and key material are not protected either: the shipped Helm chart commits a default seed, there is no spend-approval hook, and keys sit in plaintext on disk.

Scope of Analysis
A Python framework split into the uagents runtime (agent.py Agent/Bureau, asgi.py uvicorn ASGI server, dispatch.py, communication.py Dispenser, resolver.py, registration.py, network.py cosmpy ledger/Almanac client, mailbox.py, storage/) and uagents-core (ECDSA secp256k1 Identity, signed Envelope, Agentverse registration utilities). Inbound envelopes arrive at /submit on a server bound to 0.0.0.0, are signature-checked unless the sender carries a user prefix, and are dispatched by schema digest to typed handlers. Every agent also serves inspector REST endpoints by default (/agent_info, /messages, /connect, /disconnect), and keys are derived from a seed or persisted in plaintext private_keys.json. There is no LLM in the subject scope, and the repository ships a Helm chart and Dockerfiles under python/deployment/.

What's Working Well

Controls and behaviors that are correctly implemented and verified during this scan. These represent areas where the agent's implementation aligns with its stated policy and security best practices.

Envelope signature verification on by default

Every inbound envelope from an agent-prefixed sender must carry a valid secp256k1 signature over sender, target, session, schema digest, payload, expiry and nonce. A missing or bad signature is rejected before dispatch on both the HTTP and mailbox paths.

python/src/uagents/asgi.py:363

Signed-handler default refuses unverified senders

on_message defaults to allow_unverified=False, and a user-address sender that targets a signed handler gets an error reply instead of reaching the handler.

python/src/uagents/agent.py:1455

Hashed lockfile enforced in CI

python/uv.lock records sha256 hashes for every resolved package, and the CI test job installs with uv sync --locked, so dev and test builds are reproducible.

.github/workflows/ci-tests.yml:65

Opt-in per-handler ACL and rate limiting primitive

QuotaProtocol wraps handlers with an AccessControlList (allow/block sets) and a per-sender RateLimit enforced before the handler runs. This is a real primitive operators can adopt, though it is off by default.

python/src/uagents/protocol/quota.py:106

Reference deployment loads the seed from environment

The hello-agent reference reads its seed from UAGENT_SEED rather than source, and the README recommends loading the seed from an environment variable.

python/deployment/hello-agent/agent.py:6

Weighted Maturity Score · Ad hoc
Ad hoc. The runtime has one strong, operative control — signature verification on agent-sent envelopes, with a signed-handler default that refuses unverified senders — and that lifts Zero Trust and the input-facing categories to Partial. Everything around that control is opt-in or missing: there is no replay protection, no default peer allowlist, no spend gate, and the default-on inspector can be reached remotely. Supply-chain hygiene, adversarial testing and monitoring show little practice beyond a hashed lockfile and functional negative tests, so the framework hands every deployed agent an Ad hoc baseline.

Maturity Scoring Rubric

Every score above is based on this scale. A score is a snapshot of observable posture — not a verdict on the people or team behind the system.

Score Label Meaning
5 Exemplary Best-in-class; automated, continuously tested, reference quality. Rarely achieved in shipping systems.
4 Strong Comprehensive controls, active management, minor gaps. Production-ready.
3 Established Documented controls consistently applied; known gaps accepted. A respectable baseline.
2 Partial Some controls exist but coverage is incomplete; key gaps remain.
1 Ad hoc Informal or inconsistent measures; relies on individual judgment.
0 Absent No evidence this category is addressed at all.
Weighting: the weighted overall above is the sum of each category's score × weight (the per-category weights are shown on each card). Zero Trust carries double weight by design; see the RAISE framework reference for the rationale.
