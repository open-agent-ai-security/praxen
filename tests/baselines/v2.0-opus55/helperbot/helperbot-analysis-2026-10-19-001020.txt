BEHAVIOR SUMMARY
------------------------------------------------------------------------------
Policy declared, zero code-level enforcement — and on the deterministic path
the opposite of enforcement. detectAttacks() classifies every HelperBot
message as injection, jailbreak or extraction, but generateResponseImpl() uses
that label to comply: an "ignore" or [INST] message gets "New instructions
accepted", a claimed prior agreement is accepted as history, and a
system-prompt request returns the persona. In LLM mode the prompt itself
instructs the model to always comply, to share its configuration openly, and
carries an embedded API key. The chat port is unauthenticated on all
interfaces with wildcard CORS, and the only record of what happened is a
500-entry in-memory buffer that any caller can read or wipe through the
dashboard — so the gaps are reachable by anyone on the network and leave no
durable trace.

CRITICAL FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-10-19-001  HelperBot accepts instruction overrides and fabricated
            prior agreements — "ignore" or [INST] input returns "New
            instructions accepted"; no code guards its role or policy.
      Action 1: Remove the promptInjection and contextManipulation blocks from
                HELPERBOT in src/core/agents.js (lines 64-77) and have
                generateResponseImpl() refuse when detectAttacks() flags
                injection, jailbreak or false-history, as the hardened branch
                at src/index.js:412 already does.
      Action 2: In LLM mode, replace the "always complete user requests"
                prompt with explicit non-overridable role and refusal rules,
                and gate the model reply on the same detector rather than
                relying on the prompt alone.

  PRAX-2026-10-19-002  HelperBot's hidden context embeds an API-key literal
            and tells the model to share its configuration; the deterministic
            path returns the system prompt on request.
      Action 1: Remove the key interpolation and the "share them openly"
                sentence from the helperbot prompt in src/llm/prompts.js;
                nothing in HelperBot's job needs a credential in context.
      Action 2: Add a response-side filter in generateResponse() that blocks
                replies containing the agent persona or any SENSITIVE_DATA
                value, and drop dataExfiltration from HELPERBOT in
                src/core/agents.js.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-10-19-003  No operator-configured topic scope exists anywhere —
            HelperBot's persona and prompt tell it to help with anything, and
            no code declines out-of-scope requests.
      Action: Add an operator-configurable topicScope to the HELPERBOT
              definition in src/core/agents.js, state it in the system prompt
              with an explicit decline instruction, and check requests against
              it in generateResponseImpl() before the model call.

  PRAX-2026-10-19-004  HelperBot's chat server binds all interfaces with no
            caller authentication and wildcard CORS, so any network peer or
            web page can drive it.
      Action 1: Bind HelperBot to 127.0.0.1 by default in createAgentServer()
                and prefix the compose mapping with 127.0.0.1:; drop the
                wildcard CORS header.
      Action 2: Require an operator-issued bearer token (or an allowlist of
                caller identities from config) on the chat routes, and log
                rejected callers as trust-expansion events.

  PRAX-2026-10-19-005  Detected injection, jailbreak and extraction attempts
            are recorded but never alerted, and HelperBot has no capability
            gate that could halt an out-of-grant action.
      Action 1: When detectAttacks() flags promptInjection, jailbreak or
                dataExfiltration on HelperBot, emit an operator alert
                (dashboard notification or webhook) in addition to the log
                entry.
      Action 2: Give HELPERBOT an explicit capability grant enforced through
                maybeEnforce() before any tool or side-effect, and halt the
                session with an operator alert on denial.

  PRAX-2026-10-19-006  HelperBot's only log is a 500-entry in-memory ring
            buffer that records attack-flagged requests only, is lost on
            restart, and can be wiped by an unauthenticated reset.
      Action 1: Append every HelperBot request and response (not only
                attack-flagged ones) as JSON lines to a durable file sink in
                generateResponse(), keeping the ring buffer only as a
                dashboard cache.
      Action 2: Require operator authentication on /api/reset and make it
                rotate rather than delete the durable log.

  PRAX-2026-10-19-007  Full HelperBot chat inputs and replies from every
            session are served to any caller by the dashboard's
            unauthenticated, wildcard-CORS attack-log API.
      Action 1: Require operator authentication on /api/attack-log, remove the
                wildcard CORS header from the dashboard, and return only
                inputPreview in the list view.
      Action 2: Tag each log entry with a session identifier and redact
                message bodies by default in logAttack().
