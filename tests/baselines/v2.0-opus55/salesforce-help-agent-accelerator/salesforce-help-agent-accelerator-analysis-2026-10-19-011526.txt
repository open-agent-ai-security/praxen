BEHAVIOR SUMMARY
------------------------------------------------------------------------------
The dominant pattern is policy declared in prompt instructions with no
deterministic enforcement: every content-lane, disclosure, and grounding rule
in the remit is implemented as natural-language guidance in
haaHelpAgent.agent, and the shipped bundle disables citations, so nothing
outside the model distinguishes a grounded answer from an invented one. Two
concrete divergences sharpen this. The grounding action's configuration inputs
(citationsUrl, ragFeatureConfigId, citationsEnabled) are flagged
is_user_input: True while the system prompt says all function parameters come
from the messages, which lets an anonymous visitor try to steer citation links
and the retriever. The off_topic topic also offers escalation to a human
agent, which the remit forbids. The audit trail the remit makes mandatory is
documented only as an optional setup step.

HIGH FINDINGS
------------------------------------------------------------------------------
  PRAX-2026-10-19-001  The knowledge action's citationsUrl, ragFeatureConfigId
            and citationsEnabled inputs are flagged user-collectable, letting
            anonymous visitors try to steer citation links and the retriever.
      Action 1: In haaHelpAgent.agent, set is_user_input: False on
                citationsUrl, ragFeatureConfigId and citationsEnabled so they
                are bound only to the operator's @knowledge values; keep only
                query user-derived.
      Action 2: Add a deterministic post-check (or Trust Layer output rule)
                that rejects responses whose links are not on the operator's
                citation domain.

  PRAX-2026-10-19-002  The off_topic topic tells the agent to offer escalation
            to a human agent, and setup routes sessions to a fallback queue,
            contradicting the no-handoff rule.
      Action 1: In haaHelpAgent.agent, replace the off_topic line 157
                escalation offer with the website-support redirect used by the
                escalation topic, and remove "escalates complex issues" from
                config.description.
      Action 2: In the README, document that the Fallback Queue must have no
                staffed agents (or an auto-close flow) so no Messaging Session
                reaches a human.

  PRAX-2026-10-19-003  Einstein Audit and Feedback and Agentforce Session
            Tracing, which the remit makes a required setup step, are
            documented only as optional monitoring toggles.
      Action: Move the Audit and Feedback and Session Tracing toggles into the
              required Step 1.1 prerequisites and add a go-live checklist item
              that confirms they are on before the agent is activated.
