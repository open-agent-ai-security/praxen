Executive Summary
Agent Remit (as declared) · Remit v1.3
CraftBot is a self-hosted, proactive personal agent for a single owner-operator: it plans and executes multi-step computer and browser tasks, builds and operates local Living UI apps, keeps a local memory, and runs scheduled proactive work under the owner's own LLM keys. Its authorized tools are file read/edit, sandboxed code and shell execution, web search and fetch, document handling, memory search, the actions of integrations the owner has connected, and owner-installed Skills and MCP servers. The only authorized counterparty is the owner, reached through the local browser UI, the CLI or the owner's own connected messaging account. Irreversible or externally visible actions, state changes and config or credential changes require explicit owner approval, and host command execution must be approval-gated and must not inherit the credential-bearing environment.
Behavior Summary (as observed)
Policy is declared in prompts and barely enforced in code. The remit's approval gates, permission tiers, protected harness files and untrusted-content rule exist only as instructions in AGENT.md, skill files and the system prompt, while ActionManager.execute_action() runs whatever the model selects — run_shell with the full credential-bearing environment, http_request to any public host, and edits to its own config, MCP registry and session-loaded USER.md/SOUL.md. The dominant chain is untrusted web, file or tool content reaching the model unlabeled (the bundled PromptSanitizer is never called), persisting into files loaded into every future session, and driving ungated shell execution. Real code controls exist — third-party messages are diverted deterministically, OAuth callbacks bind loopback, integration tokens are stored owner-only, and per-task budgets pause on Continue/Abort — but they guard the edges, not the action loop.
Scope of Analysis
A Python asyncio agent harness: app/agent_base.py routes triggers (browser UI, CLI, scheduler, and platform listeners in craftos_integrations/) into an LLM action-selection loop executed by agent_core/core/impl/action/manager.py over 46 base actions in app/data/action/ (including run_shell, http_request and write_file), roughly 1,120 integration actions, and a 157-entry MCP registry in app/config/mcp_config.json. Session context is assembled from the agent file system (AGENT.md, USER.md, SOUL.md, PROACTIVE.md) plus a ChromaDB memory index, and a localhost aiohttp/WebSocket server in browser_adapter.py serves the UI and the Living UI integration bridge. Living UI backends run as spawned uvicorn subprocesses, and the Docker Compose deployment adds a desktop VM and an OmniParser container. Approval, permission tiers and injection defence live almost entirely in prompts and skill files rather than in the execution path.

1 Ad hoc Informal or inconsistent measures; relies on individual judgment.
